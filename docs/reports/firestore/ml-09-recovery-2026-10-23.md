Se conservan rangos disjuntos, barreras al dividir, orden estable y búsqueda global

## Límites explícitos

Las admisiones cuentan peticiones/intentos locales, no documentos, lecturas de
reglas ni cuota global. El almacenamiento nuevo contiene solo un timestamp,
sin UID, obras ni mensajes. Si el navegador deniega almacenamiento, sigue la
pausa en memoria; no se promete coordinación tras recarga. Otros dispositivos,
perfiles y orígenes no comparten esa pausa. Cambiar reloj o almacenamiento puede
eludirla: no es barrera de seguridad ni garantía global.

El SDK puede reconectar dentro del minuto; no se garantiza un número exacto de
intentos internos. Temporizadores de pestañas suspendidas dependen del navegador.
No se termina la instancia ni se cancelan escrituras pendientes al recuperar:
una respuesta tardía puede corresponder a un commit aplicado. Se mantiene el aviso
de cambios pendientes, sin declarar fracaso por timeout ni éxito sin acuse.
El plazo nuevo limita listeners; no promete abortar operaciones ya admitidas.
Vencer la pausa permite reintentar, nunca certifica reinicio de cuota. No hay
temporizador de reapertura automática. La exportación paginada sigue sin ser una
instantánea atómica entre páginas.

## Reproducción local

Usar Node de `.nvmrc`, Java 21+, ambos lockfiles, Firebase CLI y Playwright.

```sh
npm ci
npm ci --prefix src-pwa
npx playwright install chromium firefox
npm test
node scripts/test-firestore-local.mjs
npm run test:e2e
npm run lint:check
npm run check:spark
npm run docs:build
npm run docs:check
```

Los runners usan localhost y proyectos demo. E2E inyecta resource-exhausted en el
presupuesto real; callbacks, canales, UI, recarga y nueva escucha son de la app.
El avance del reloj simula vencimiento local, **no reinicio real de cuota**.
La prueba Firestore usa listeners SDK reales con ese error sintético.

Para builds, definir las seis variables VITE_FIREBASE con valores demo de CI,
ejecutar `npm run build`, `npm run build:pwa` y verificar ambos mediante
`node scripts/build-evidence.mjs verify spa --project demo-mangalist` (también pwa).
Después ejecutar `npm run test:pwa`. No ejecutar deploy ni el guard remoto.
Los resultados reproducibles se entregan en `proposals/ml09/evidence/`; las
trazas voluminosas quedan en `test-results/`, ignorada por Git. Los intentos
interrumpidos o fallidos no se cuentan como verificaciones aprobadas.

## Suspensión nativa y recuperación explícita

El Redmi 9A (Android 11, Chrome 155) reprodujo una sesión con 500 obras que,
tras congelar el documento, conservaba una versión anterior de un cambio confirmado
en el emulador durante más de un minuto. No se atribuye una causa interna concreta
al SDK. El control activo sí recibió el cambio y una prueba de 50 obras también
recuperó; esos éxitos no se usaron para aprobar el caso fallido de 500.

La candidata ahora escucha el evento documental `freeze`: retira todos los rangos,
propaga `app/listener-suspended` a las pestañas que compartían la escucha y exige
reintento manual. El estado anterior queda sin confirmación y con aviso; no se
mantiene como comprobación actual. El registro del evento se elimina al detener la
suscripción. No hay reapertura automática ni robo de la propiedad de otra pestaña.

`library-recovery.js` prepara el reintento explícito mediante `disableNetwork` y
`enableNetwork` de la instancia local, sin terminarla ni borrar cachés. La
[referencia oficial del SDK](https://firebase.google.com/docs/reference/js/firestore#disablenetwork)
establece que las escrituras quedan en cola hasta restaurar la red. Se verifica
con el emulador que la promesa original de una escritura pendiente termina con
confirmación del mismo documento y que otra cuenta sigue sin acceso.

La preparación es única en vuelo y admite como máximo tres intentos por minuto,
además del presupuesto de escucha y su backoff; una pausa de cuota impide tocar
el transporte. Se comprueba la identidad antes y después. Siempre se intenta
restaurar la red incluso si falla la pausa, y se preservan ambas causas si fallan
las dos fases. Ni restaurar el transporte ni expirar la pausa acreditan confirmación
del servidor: sigue siendo necesaria la barrera completa de la nueva escucha.

La regresión de dos pestañas congela de verdad el antiguo dueño, comprueba su
retirada, conserva una escritura concurrente y la búsqueda, y recupera 500 obras
mediante un único relevo explícito. Cerrar después el dueño retirado no abre otra
escucha. La prueba física registra funciones de tiempo nativas, congelación de
unos 20 segundos, cero targets nuevos antes del reintento y una exportación de
500 IDs únicos con el cambio confirmado. Es congelación del documento en un móvil
físico; no certifica suspensión del sistema operativo, Safari ni cuota global.

Los primeros ensayos fallidos y los controles de instrumentación se conservan en
la entrega; no se reescriben como aprobados. La causa se mitiga con reconexión manual
segura, sin inventar métricas de producción ni cancelar escrituras ya admitidas.
