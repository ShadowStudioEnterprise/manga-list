La persistencia del servicio usa localStorage con fallback a memoria. LocalStorage
comparte una identidad por origen: las cuentas simultáneas necesitan perfiles o
clientes independientes. El fallback evita que falle el arranque, pero no promete
persistencia ni sincronización entre pestañas si el almacenamiento está bloqueado.
La recarga y nueva pestaña no certifican reiniciar todo el navegador o el teléfono.
Un token vencido no significa necesariamente terminar la sesión: puede renovarse.

## Ejecución y aislamiento

```sh
npm ci
npm run lint:check
npm test
npm run check:spark
npm run docs:build
npm run docs:check
node scripts/test-firestore-local.mjs
npm run test:auth
```

`test:auth` arranca Auth 9199, Firestore 8188 y Quasar 9100 en loopback,
proyecto demo-mangalist. Ejecuta la suite nueva y las regresiones library en
Chromium y Firefox, con una sola worker y sin reutilizar servidores. Las
peticiones de navegador fuera de esos puertos se abortan. La sonda exacta
cleardot de Firestore se bloquea; A12 cuenta y bloquea el bootstrap Google.
Las APIs administrativas locales de recuperación nunca se derivan de un .env
real. El reporter JSON queda en test-results/browser-results.json; CI lo conserva.

En Windows puede ser necesario anteponer el bin del JDK real al PATH por el shim
Oracle. La primera instalación offline no tenía todas las dependencias en caché;
se completó npm ci con el lockfile. El primer intento unitario dio 136/138 por
permisos de symlink/git temporales del sandbox; fuera de él pasó 138/138 antes
de añadir tres unitarios ML-15. No se atribuyen esos fallos al producto.

La primera suite exploratoria tenía un selector de biblioteca vacía incorrecto
y esperaba un popup aunque la red bloqueaba el bootstrap Google. Ambos fallos
de instrumental se conservan en el expediente local. No se usa un mock de popup
para declarar PASS de OAuth. No se confirmó un defecto de aplicación que exigiera
modificar el servicio Auth; la rama incorpora pruebas y documentación.

Para Android: crear túneles ADB reverse
9100/9199/8188 y forward 9227 al socket chrome_devtools_remote. Ejecutar
`MANGALIST_ANDROID_DEMO=true npm run test:auth:android` usando la sintaxis
de variables del shell correspondiente. Este runner mantiene sus propios emuladores y servidor durante todo el ensayo; el script interno también puede usarse con servidores demo ya activos. El script solo inspecciona pestañas nuevas
de localhost; no enumera ni lee pestañas personales. Captura biblioteca sintética,
cierra sus pestañas y termina sin sesión. Logout móvil invoca el servicio real
desde la página y los formularios se envían con Enter; la navegación a registro usa el enlace del router. No acredita gestos del menú táctil. Se deben retirar únicamente
los túneles creados para esta prueba, preservando cualquier túnel previo.

Android carga api.js proactivamente incluso para email: la primera ejecución
completó los seis pasos pero falló el contador de aislamiento por esas solicitudes
abortadas. Hubo además fallos de coordenadas CDP, navegación por hash, espera y cierre prematuro del servidor compartido. La ejecución final con servidor propio pasó los seis pasos en 16,3 s y contabilizó tres bootstraps api.js abortados. No se permite completar OAuth ni se autentica una cuenta del teléfono. Los túneles creados se retiraron al terminar.
